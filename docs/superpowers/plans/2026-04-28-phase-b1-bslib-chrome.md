# Phase B1 — bslib chrome + theme swap — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `shinydashboard` UI shell with `bslib::page_navbar` + per-tab `layout_sidebar`, swap chrome to a Slate + OK-blue theme with light/dark toggle, migrate all 22 `shinydashboard::box()` call sites to `bslib::card()`, and drop `shinydashboard` from `Imports`.

**Architecture:** `page_navbar` with 5 nav panels (Data Prep / Main Plots / QC Plots / GO Term / Tables). Data Prep tab uses `bslib::navset_pill_list(id = "DataPrep")` for the wizard step nav (preserves `input$DataPrep`). Main Plots tab uses `layout_sidebar` for the plot-controls sidebar (formerly the "Discover" sidebar tab). Server-side observers replace the JS reveal logic for progressive wizard step disclosure. No analytical code changes.

**Tech Stack:** R, Shiny, bslib (>= 0.7.0), shinyjs (kept for behavior, dropped from chrome), DT, plotly. R package layout (DESCRIPTION/NAMESPACE/man/), testthat 3e.

**Spec:** [docs/superpowers/specs/2026-04-28-phase-b1-bslib-chrome-design.md](../specs/2026-04-28-phase-b1-bslib-chrome-design.md)

- [ ] **Step 4: Create R/de_card.R**

```r
#' de_card
#'
#' DEBrowser card wrapper used at every former `shinydashboard::box()` site.
#' Optionally renders a small primary download button on the right of the
#' card header.
#'
#' @param title character — card title shown in the header
#' @param ... card body content
#' @param download_id character or NULL — if non-NULL, render a
#'   `downloadButton` with this id in the header
#' @param full_screen logical — passed through to `bslib::card()`
#'
#' @return a `bslib::card` tagList
#' @examples
#' x <- de_card("Heatmap", plotOutput("heat"))
#' @export
de_card <- function(title, ..., download_id = NULL, full_screen = TRUE) {
  header <- if (is.null(download_id)) {
    bslib::card_header(title)
  } else {
    bslib::card_header(
      class = "d-flex align-items-center",
      title,
      shiny::tags$div(
        class = "ms-auto",
        shiny::downloadButton(
          download_id,
          label = NULL,
          icon  = shiny::icon("download"),
          class = "btn-primary btn-sm"
        )
      )
    )
  }
  bslib::card(header, ..., full_screen = full_screen)
}
```

togglePanels <- function(num = NULL, nums = NULL, session = NULL) {
  if (is.null(num)) {

  for (i in 0:4) {
    target <- paste0("panel", i)
    if (i %in% nums) {
      bslib::nav_show("methodtabs", target = target, session = session)

      bslib::nav_hide("methodtabs", target = target, session = session)
    }

                      session = session)
  }
}

## Risks & rollback notes

If a task breaks the live app and rollback is needed:

- Each task ends with a single commit, so `git reset --hard <prior-commit>` rolls back exactly that task.
- The `box()` migration sub-tasks (5.1–5.15) are independent — a single bad migration can be reverted without unwinding the others.
- The shell rewrite (Task 2) is the largest single diff and the highest blast-radius. If it fails to boot, revert and inspect `nav_panel`/`navset_pill_list` versions of bslib (the pinned `>= 0.7.0` should be sufficient; older versions may not have `navset_pill_list`).

If `bslib::nav_show`/`nav_hide` doesn't behave as expected for a given navset (e.g., bslib version differs from spec assumption), fall back to `shinyjs::show`/`hide` with a CSS selector targeting the nav-link's `data-value` attribute. This is a localized change in `togglePanels()` and the wizard observers; doesn't require unwinding the rest of the migration.
