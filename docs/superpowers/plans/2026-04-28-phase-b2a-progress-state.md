# Phase B2a — Progress state, decoration, gating, auto-nav — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a single source-of-truth progress reactiveValues to `deServer`, decorate the Data Prep outer nav title and the sidebar wizard pills with done/locked states, auto-show the QC tab on counts-load, and auto-navigate to Main Plots after DE completes. No new dependencies.

**Architecture:**
- New `progress` reactiveValues in `deServer` tracks pipeline progress (upload/filter/batch/de). State changes are pushed to the browser as Shiny custom messages keyed by name.
- A small JS handler (replacing the existing no-op `getTabUpdateJS()`) reads each message and toggles CSS classes on icon `<span>`s and on parent `<a>` pills. CSS provides the visual treatment.
- Tab visibility continues to use the existing imperative `togglePanels()` helper from `R/uifuncs.R`. The `progress` reactiveValues drives icons only — *not* tab visibility — so there is one source of truth for each concern.

**Tech Stack:** R, Shiny, bslib, testthat. No new R dependencies.

**Spec:** [`docs/superpowers/specs/2026-04-28-phase-b2-wizard-polish-design.md`](../specs/2026-04-28-phase-b2-wizard-polish-design.md), section "B2a — State + decoration + gating + auto-nav".

**Behavior change (intentional, from spec):**
- Today: the QC Plots tab (`panel2`) becomes visible only when the user clicks `goQCplots` / `goQCplotsFromFilter`.
- After B2a: the QC Plots tab auto-appears on counts-load (no button click required). The buttons still work; their handlers stay as-is.
- Today: after DE finishes, the user must click the `goMain` button to unlock plot/GO/Tables tabs and switch to Main Plots.
- After B2a: those tabs auto-unlock and the navbar auto-selects Main Plots when DE finishes. The `goMain` button observer is preserved for back-navigation but no longer load-bearing in the golden path.

#' Compute the CSS class name for a pill given its progress state.
#'
#' Used by the JS handler in `getTabUpdateJS()` (R/funcs.R) and as a
#' direct render path for static initial state.
#'
#' @param state character, progress state.
#' @return character, CSS class name or empty string.
#'
#' @examples
#' compute_pill_class("done")

compute_pill_class <- function(state) {
  switch(state,
    "done"    = "de-pill-done",
    "skipped" = "de-pill-done",
    "locked"  = "de-pill-locked",
    ""
  )
}

```r
#' Push a progress update to the browser for one key.
#'
#' Sends a Shiny custom message of type "debrowser-progress" with a
#' payload built by `progress_message(key, state)`. The handler installed
#' by `getTabUpdateJS()` (R/funcs.R) reads the message and toggles CSS
#' classes on the matching icon span and parent pill.
#'
#' @param session Shiny session object.
#' @param key character, progress key.
#' @param state character, progress state.
#' @return Invisibly NULL.
#'
#' @examples
#' \dontrun{
#'   update_progress(session, "upload", "done")
#' }
#'
#' @export
update_progress <- function(session, key, state) {
  session$sendCustomMessage(
    "debrowser-progress",
    progress_message(key, state)
  )
  invisible(NULL)
}
```

Replace with:

```r
getTabUpdateJS <- function() {
  # B2a: install a Shiny custom-message handler that toggles CSS classes
  # on progress icons (.de-progress-icon[data-progress-key=...]) and on
  # parent pills (a[data-progress-pill=...]). The server side calls
  # update_progress(session, key, state) to drive these.
  tags$script(HTML(
    "Shiny.addCustomMessageHandler('debrowser-progress', function(msg) {",
    "  var iconSel = '.de-progress-icon[data-progress-key=\"' + msg.key + '\"]';",
    "  document.querySelectorAll(iconSel).forEach(function(el) {",
    "    el.classList.remove('done', 'locked', 'skipped');",
    "    if (msg.state === 'done' || msg.state === 'locked' || msg.state === 'skipped') {",
    "      el.classList.add(msg.state);",
    "    }",
    "  });",
    "  var pillSel = 'a[data-progress-pill=\"' + msg.key + '\"]';",
    "  document.querySelectorAll(pillSel).forEach(function(el) {",
    "    el.classList.remove('de-pill-done', 'de-pill-locked');",
    "    if (msg.state === 'done' || msg.state === 'skipped') {",
    "      el.classList.add('de-pill-done');",
    "    } else if (msg.state === 'locked') {",
    "      el.classList.add('de-pill-locked');",
    "    }",
    "  });",
    "});"
  ))
}
```

Note: `HTML(...)` accepts multiple character arguments and concatenates with newlines.
